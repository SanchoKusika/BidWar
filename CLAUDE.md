# BidWar — рабочие правила

Telegram Mini App: платный и бесплатный топы проектов. Позиция в платном покупается
(Raise) и отбирается (Attack), в бесплатном зарабатывается голосами за задания.

## Прежде чем начать задачу

**Спецификация лежит вне репозитория,** в Obsidian: `~/Documents/Obsidian Storage/Проекты/BidWar/`
(13 файлов, `00 Обзор` … `12 Состояние реализации`). Требования брать оттуда, а не
восстанавливать по коду.

Читать в таком порядке:

1. `12 Состояние реализации` — **что реально работает, а что только нарисовано.** Здесь же
   список известных мелких дефектов, чтобы не искать их заново.
2. `08 План разработки` — порядок срезов и что делает текущий.
3. Профильный документ под задачу: `01 Механики`, `03 Данные`, `04 Платежи и валюты`,
   `05 Аккаунты и авторизация`, `06 Telegram-бот и Mini App`.

Если документ разошёлся с кодом — правда в коде, а документ надо починить тем же
заходом. Расхождение, оставленное на потом, обходится дороже правки.

## Состояние (сверять с документом 12, здесь только ориентир)

Закрыты срезы 1.1–1.4 плюс полный перенос вёрстки из дизайн-кита. Следующий —
**1.5: платёжный слой на моке и Raise**.

**Денег в продукте нет ни одной строкой.** Платного входа, Raise и Attack не
существует. При этом вёрстка перенесена вся, включая экраны ещё не написанных
механик, — не принимай нарисованное за работающее.

**Автотестов нет ни одного, раннера тоже.** Ставится вместе с платёжным моком.

## Git

- Conventional Commits, **сообщения на английском**, тело только когда изменение
  правда требует объяснения.
- **Никогда не добавлять трейлер `Co-Authored-By`.**
- Не работать напрямую в `main`: ветка под кусок работы → коммиты → `gh pr create` →
  мерж. Squash-мерж, ветку удалять.
- Историю не переписывать. Шесть старых коммитов с русскими сообщениями оставлены
  намеренно, force-push в `main` не делать.

## Перед пушем

```bash
npm run check     # типы + линт + prettier + изоляция платформы
```

Состав **намеренно совпадает с CI**. Добавляешь проверку в пайплайн — добавь и в
`check`, иначе расхождение всплывёт уже красным после пуша (так и случилось однажды
с `format:check`).

## Правила кода

**Структура — FSD.** Слой ниже не знает про слой выше: `app > pages > widgets >
features > entities > shared`. Нарушение ловит `no-restricted-imports` в
`eslint.config.js` для `entities`, `features`, `shared`, `pages/*/model`.

**Ничто вне `shared/platform` и `app/telegram` не трогает `window.Telegram`.**
Проверяется `scripts/check-platform-isolation.sh` в CI. Это единственное, что
удерживает возможность сделать веб в Этапе 2, не переписывая фичи.

**Только CSS-модули, значения из токенов** (`shared/ui/tokens/*.css`). Инлайн-стиль
допустим единственным способом — пробросить динамическое значение в CSS-переменную:

```tsx
style={{ '--og-size': `${size}px` } as CSSProperties}
```

Захардкоженных цветов вне `tokens/` в проекте нет — так и держать.

**Бизнес-правила живут на сервере.** Лимиты ставок и коэффициенты атаки — в
`app_config.paid_limits`, клиент читает их через `fetchPaidLimits` и использует
**только для предпросмотра**; окончательный расчёт делает сервер. Дублировать эти
числа константами в клиенте нельзя — расхождение здесь стоит денег.

**Блоки без источника данных — за флагами** в `shared/config/preview.ts`. По этому
файлу видно границу между витриной и работающей функцией. Подключение фичи — это
убрать флаг вместе с его ветками.

Если элемент выглядит рабочим, но ничего не делает, — его надо **прятать, а не
дизейблить**: неработающая кнопка врёт пользователю сильнее, чем отсутствующая.
Так спрятан `todayScope`. Кнопки Raise/Attack/Vote — обратный случай: они честно
задизейблены, потому что механика заявлена и придёт.

## Ловушки, на которые уже наступали

**`react-hooks/set-state-in-effect`** — нельзя вызывать `setState` синхронно в теле
эффекта. Сброс состояния при смене пропа делается сравнением в рендере с зеркалом в
`useState`:

```tsx
const [loadedId, setLoadedId] = useState(id);
if (loadedId !== id) {
  setLoadedId(id);
  setStatus('loading');
}
```

**`react-hooks/refs`** — не мутировать `.current` во время рендера.

**`noUncheckedIndexedAccess: true`** — обращение по индексу даёт `T | undefined`.
Для гарантированно непустых списков объявлять непустой кортеж:
`readonly [PaymentProvider, ...PaymentProvider[]]`.

## Язык

Комментарии в коде, документация и PR-описания — **по-русски**. Сообщения коммитов —
по-английски. Интерфейс сейчас английский, строки собраны в `shared/i18n/strings.ts`
под будущие RU/UZ/EN.

Комментарий объясняет **почему**, а не что: «что» видно из кода.

## Инфраструктура

- **Edge Functions деплоятся руками**, в CI их нет: `npx supabase functions deploy <name>`.
- Фронт выкладывается автоматически на каждый пуш (Cloudflare Pages).
- После миграции — `npm run db:types`, файл генерируемый.
- Одно развёртывание отвечает на трёх хостах: `bidwar.world` (сайт, Этап 2),
  `app.bidwar.world` (мини-апп), `bidwar.pages.dev` (служебный алиас Pages, несносим).
  Индексируется только первый, остальные закрыты `X-Robots-Tag` в `public/_headers`.

Подробности стека, команд и деплоя — в `README.md`.
