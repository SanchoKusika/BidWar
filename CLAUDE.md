# BidWar — рабочие правила

Telegram Mini App: платный и бесплатный топы проектов. Позиция в платном покупается
(Raise) и отбирается (Attack), в бесплатном зарабатывается голосами за задания.

## Прежде чем начать задачу

**Спецификация лежит вне репозитория,** в Obsidian: `~/Documents/Obsidian Storage/Проекты/BidWar/`
(13 файлов, `00 Обзор` … `12 Состояние реализации`). Требования брать оттуда, а не
восстанавливать по коду.

Читать в таком порядке:

1. `12 Состояние реализации` — **что реально работает, а что только нарисовано.** Здесь же
   список известных мелких дефектов, чтобы не искать их заново.
2. `08 План разработки` — порядок срезов и что делает текущий.
3. Профильный документ под задачу: `01 Механики`, `03 Данные`, `04 Платежи и валюты`,
   `05 Аккаунты и авторизация`, `06 Telegram-бот и Mini App`.

Если документ разошёлся с кодом — правда в коде, а документ надо починить тем же
заходом. Расхождение, оставленное на потом, обходится дороже правки.

## Состояние (сверять с документом 12, здесь только ориентир)

Закрыты срезы 1.1–1.6 плюс полный перенос вёрстки из дизайн-кита и разбор
замечаний по 1.6 (PR #33 и #34, 02.09.2026). Следующий — **1.7: задания и
голоса**.

**Платный вход, Raise и Attack работают на моке.** `apply_payment` —
единственная хранимка, двигающая деньги и очки, идемпотентна, блокирует строки
по возрастанию `id`; Attack живёт внутри неё же. Raise работает и по чужому
проекту — это донат в его ставку, а не перевод владельцу (`01 Механики`).
**Vote — единственная механика, которой нет**, при том что `VoteSheet`
свёрстана: не принимай нарисованное за работающее.

Настоящий рубеж между тестовым контуром и боевым — переменная окружения
Edge Functions `PAYMENT_PROVIDER=mock`, а не флаг `PREVIEW.mockPayments`:
последний красит только список способов оплаты в `PaySheet` (найдено
финальным ревью 1.5 — молчаливый дефолт `?? 'mock'` в `registry.ts` делал
незаданную переменную неотличимой от мока; дефолта больше нет, `getProvider()`
бросает, если переменная не задана). Платежи пока идут через мок, платное #1
можно занять бесплатно. **`PAYMENT_PROVIDER` обязан смотреть на настоящего
провайдера до боевого запуска** — это первое, что проверяют в чек-листе
запуска, флаг `PREVIEW.mockPayments` снимается тем же заходом, но он
косметический.

**Тесты есть, раннер `deno test`.** `npm run test` — 85 быстрых тестов без базы,
входит в `npm run check` и в CI. `npm run test:db` — интеграционные тесты
хранимок против живой базы, требует `SUPABASE_DB_URL`, в `check` и CI не
входит намеренно.

## Git

- Conventional Commits, **сообщения на английском**, тело только когда изменение
  правда требует объяснения.
- **Никогда не добавлять трейлер `Co-Authored-By`.**
- Не работать напрямую в `main`: ветка под кусок работы → коммиты → `gh pr create` →
  мерж. Squash-мерж, ветку удалять.
- Историю не переписывать. Шесть старых коммитов с русскими сообщениями оставлены
  намеренно, force-push в `main` не делать.

## Перед пушем

```bash
npm run check     # типы + линт + prettier + изоляция платформы + npm run test
```

Состав **намеренно совпадает с CI**. Добавляешь проверку в пайплайн — добавь и в
`check`, иначе расхождение всплывёт уже красным после пуша (так и случилось однажды
с `format:check`).

`npm run test` (`deno test`, нужен установленный Deno) гоняет тесты Edge Functions —
без сети и без базы. Отдельно, руками, перед пушем миграции, трогающей хранимки:
`npm run test:db` — интеграционные тесты против **живой** базы, требует
`SUPABASE_DB_URL` в `.env`. В `check` и CI намеренно не входит.

## Правила кода

**Структура — FSD.** Слой ниже не знает про слой выше: `app > pages > widgets >
features > entities > shared`. Нарушение ловит `no-restricted-imports` в
`eslint.config.js` для `entities`, `features`, `shared`, `pages/*/model`.

**Ничто вне `shared/platform` и `app/telegram` не трогает `window.Telegram`.**
Проверяется `scripts/check-platform-isolation.sh` в CI. Это единственное, что
удерживает возможность сделать веб в Этапе 2, не переписывая фичи.

**Только CSS-модули, значения из токенов** (`shared/ui/tokens/*.css`). Инлайн-стиль
допустим единственным способом — пробросить динамическое значение в CSS-переменную:

```tsx
style={{ '--og-size': `${size}px` } as CSSProperties}
```

Захардкоженных цветов вне `tokens/` в проекте нет — так и держать.

**Бизнес-правила живут на сервере.** Лимиты ставок и коэффициенты атаки — в
`app_config.paid_limits`, клиент читает их через `fetchPaidLimits` и использует
**только для предпросмотра**; окончательный расчёт делает сервер. Дублировать эти
числа константами в клиенте нельзя — расхождение здесь стоит денег.

**Блоки без источника данных — за флагами** в `shared/config/preview.ts`. По этому
файлу видно границу между витриной и работающей функцией. Подключение фичи — это
убрать флаг вместе с его ветками.

Флаг — не единственный способ: где источник приходит пропом, честнее обойтись
без него. `ShowcaseScreen` рисует ленту событий и переключатель «All time /
Today», только если страница передала им данные, — у бесплатного топа их не
будет до 1.7, и блоки там просто отсутствуют.

Если элемент выглядит рабочим, но ничего не делает, — его надо **прятать, а не
дизейблить**: неработающая кнопка врёт пользователю сильнее, чем отсутствующая.
Так спрятаны переключатели настроек без обработчика (`settingsStubs`) и кнопка
«поделиться» без `onShare`. Кнопка Give votes — обратный случай: она честно
задизейблена, потому что механика заявлена и придёт в 1.7.

**Число всегда идёт со своей единицей, и единица не врёт.** Внутри всё считается
в очках (1 очко = 1 сум), на экран число выходит **в валюте зрителя**
(`04 Платежи и валюты`). Поменять подпись, не пересчитав число, — готовый баг:
ровно так поле ввода показывало «50 000 $» вместо «4.13 $». Исключение —
чек и история платежей: там показывается ровно то, что списано, и это не
пересчитывается никогда.

**Витрины ходят через кэш** `shared/lib/query.ts` (stale-while-revalidate).
Отсюда два разных флага вместо одного: `loading` — показывать нечего, уместен
скелетон; `refreshing` — на экране прошлый ответ, свежий в пути. Там, где ждут
именно свежие данные (ранг в квитанции после оплаты), проверять надо
`refreshing`.

## Ловушки, на которые уже наступали

**`react-hooks/set-state-in-effect`** — нельзя вызывать `setState` синхронно в теле
эффекта. Сброс состояния при смене пропа делается сравнением в рендере с зеркалом в
`useState`:

```tsx
const [loadedId, setLoadedId] = useState(id);
if (loadedId !== id) {
  setLoadedId(id);
  setStatus('loading');
}
```

**`react-hooks/refs`** — не мутировать `.current` во время рендера.

**`noUncheckedIndexedAccess: true`** — обращение по индексу даёт `T | undefined`.
Для гарантированно непустых списков объявлять непустой кортеж:
`readonly [PaymentProvider, ...PaymentProvider[]]`.

## Язык

**Всё, что уходит в репозиторий, пишется по-английски:** сообщения коммитов,
описания pull request'ов и комментарии в коде. Решено 02.09.2026 — до этого
комментарии и PR-описания были русскими.

Исключения, и они не про язык, а про адресата:

- **спецификация в Obsidian** — документ автора, остаётся русской;
- **`README.md` и этот файл** — написаны по-русски и переводятся не по одной
  фразе, а отдельным заходом, если он понадобится;
- **уже написанные русские комментарии** не переводятся задним числом:
  правишь функцию — комментарий рядом становится английским, остальное
  не трогаешь. Смешанный код на время миграции — меньшее зло, чем диффы,
  в которых правка утонула среди переводов.

Интерфейс приложения английский, строки собраны в `shared/i18n/strings.ts`
под будущие RU/UZ/EN.

Комментарий объясняет **почему**, а не что: «что» видно из кода.

## Инфраструктура

- **Edge Functions деплоятся руками**, в CI их нет: `npm run functions:deploy`
  выкладывает все разом. `verify_jwt` каждой прописан в `supabase/config.toml` —
  без него массовый деплой включит проверку JWT двум вебхукам (`bot`,
  `payment-webhook`), которых зовут без заголовка `Authorization`. Разъехавшийся
  деплой уже стоил среза: в проде висела `create-payment` от 1.5, и **любая
  атака отвечала ошибкой валидации**, хотя код в `main` был верный.
- Фронт выкладывается автоматически на каждый пуш (Cloudflare Pages).
- После миграции — `npm run db:types`, файл генерируемый.
- Одно развёртывание отвечает на трёх хостах: `bidwar.world` (сайт, Этап 2),
  `app.bidwar.world` (мини-апп), `bidwar.pages.dev` (служебный алиас Pages, несносим).
  Индексируется только первый, остальные закрыты `X-Robots-Tag` в `public/_headers`.

Подробности стека, команд и деплоя — в `README.md`.
